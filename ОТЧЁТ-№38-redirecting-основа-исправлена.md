# Отчёт №38 — «всё равно Redirecting...»: корень найден, лечение без отката Nuxt

## Симптом

После поставки №37 (откат nuxt 4.6.2 + предохранитель) exe всё равно показывает
«Redirecting...». Возможные причины у пользователя: откат не применился к
установленным пакетам (нужен `pnpm install`), guard завершал пайплайн с ошибкой,
а запускаться продолжал старый exe. В любом случае подход «откат версии»
хрупкий — в №38 причина найдена точно и лечение сделано устойчивым к версии.

## Корень бага (уточнён в №38, воспроизведён на стендах)

Проблема — **не абстрактный баг nitro-server 4.6.3, а конкретная несовместимость
с `app.baseURL: './'`** (в конфиге проекта base был относительным для file://).

Цепочка на nuxt 4.6.3 (+ Nitro 2.13.4/2.13.5 — без разницы):

1. `app.baseURL: './'` → nitro-server 4.6.3 не находит обработчик для
   prerender-запроса `/` (в логе generate маршрут `/` молча отсутствует).
2. Запрос падает в 404.
3. Error-хендлер nitro (`nitropack/dist/runtime/internal/error/prod.mjs`) при
   statusCode 404 и baseURL-«подпути» возвращает 302 с телом `Redirecting...`
   (ветка «redirect to baseURL»).
4. Prerenderer записывает тело ответа как JSON → в `index.html`, `200.html`,
   `404.html` оказывается ровно 16 байт: `"Redirecting..."` (с кавычками).
5. `main.cjs` грузит `.output/public/index.html` → окно показывает заглушку.

**Решающее доказательство**: на стенде с nuxt 4.6.3 замена `baseURL: './'` →
`baseURL: '/'` даёт полноценный SPA-шелл (2802 байта) без каких-либо других
изменений. На 4.6.2 обе версии конфига работают (совместимость в обе стороны).

Проверка file://-безопасности при `baseURL: '/'`: в собранных чанках
`.output/public/_nuxt/*.js|css` абсолютных ссылок `/_nuxt/` НЕТ (все импорты
относительные `./X.js`); абсолютные ссылки остаются только в HTML — их и
переписывает `fix-electron-paths.mjs`. То есть `'./'` в конфиге никогда реально
не обеспечивал относительность — её обеспечивал скрипт.

## Лечение №38 (два слоя)

1. **`nuxt.config.ts`: `app.baseURL: '/'`** — устраняет 404 при prerender;
   Nuxt 4.6.3 (и новее) снова пишет полноценный SPA-шелл. Комментарий в конфиге
   объясняет, почему `'./'` возвращать нельзя.
2. **`scripts/fix-electron-paths.mjs` v2** — страховка на любой случай:
   - фаза REWRITE — прежняя перезапись `"/_nuxt/` → `"./_nuxt/`, favicon;
   - фаза STUB-DETECT/REPAIR — если HTML всё же заглушка («Redirecting...»,
     < 200 байт, нет `<title`/`#entry`), скрипт **восстанавливает SPA-шелл
     сам**: entry-чанк ищется по сигнатурам сборки (`__vite__mapDeps` +
     `NUXT_DATA` — уникальны, проверено на 4.6.2 и 4.6.3), стили —
     `entry.*.css`, buildId — `_nuxt/builds/latest.json`; восстановление для
     index/200/404;
   - фаза VERIFY — каждая локальная ссылка финального index.html (href/src/
     importmap `#entry`) обязана существовать на диске; битые функциональные
     ссылки → exit 1 (битый exe не соберётся); отсутствие favicon — только
     предупреждение (favicon не попадал в .output/public и в рабочих сборках).

Откат на 4.6.2 больше не требуется: №38 работает с 4.6.2 и с 4.6.3.

## Состав поставки №38

- `nuxt.config.ts` — `baseURL: '/'` + комментарий-предупреждение.
- `scripts/fix-electron-paths.mjs` — v2 (REWRITE + REPAIR + VERIFY).
- `journal-kpp-no38-spa-shell-fix.patch` — оба файла; проверен `git apply
  --ignore-whitespace` на чистую базу HEAD (байт-в-байт). Если файл уже
  отличается (например, стоит guard из №37) — применяйте копированием.
- `journal-kpp-no38-spa-shell-fix-delivery.zip` — всё вместе.

## Если после №38 что-то не так

- Вывод скрипта теперь диагностичен: exit 0 = в exe уйдёт рабочий index.html;
  exit 1 = «ВЕРИФИКАЦИЯ ПРОВАЛЕНА» — присылайте вывод.
- «Redirecting...» в запущенном exe при exit 0 = запускается старый exe:
  проверьте дату файла в `dist-electron/` и пересоберите по шагам из
  КАК-ПРИМЕНИТЬ.txt.
