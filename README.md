# Журнал КПП

Симулятор пропускного пункта с электронным журналом: пешеходы и машины,
калитка и шлагбаум, смены, записи въезда/выезда, поощрения и штрафы.
Electron-приложение на Nuxt 4 — работает как офлайн-десктоп (portable exe)
и как веб-приложение в dev-режиме.

    ⚠️ Учебный проект. Люди, автомобили и события генерируются симулятором
    и вымышлены. Не использовать как реальный журнал КПП или средство
    контроля доступа.

## Стек

- Фреймворк: Nuxt 4.6 + Vue 3.5 (`ssr: false`, hash-роутинг, `baseURL: './'` — под Electron)
- Роутинг: файловый роутинг Nuxt (Vue Router 5)
- Стили: TailwindCSS 4 + daisyUI 5
- Шаблоны: Pug (`@vue/language-plugin-pug`)
- Анимация: GSAP 3 (шлагбаум, калитка)
- Графики: Chart.js 4 + vue-chartjs (отчёты)
- Поиск: Fuse.js (нечёткий поиск по журналу/людям)
- Хранилище: IndexedDB (БД v11, 7 сторов: `people`, `vehicles`, `journal`, `settings`, `shifts`, `scenes`, `payroll`) — см. `app/composables/useDatabase.ts`
- Десктоп: Electron 44 + electron-builder 26 (портативный exe)
- Тесты: vitest 4 + happy-dom
- Язык: TypeScript 5.9
- Пакетный менеджер: pnpm

## Требования

- Node.js: 22.x или 24.x (LTS)
- pnpm: 10 или новее
- ОС: Windows 10/11 (сборка exe), Linux, macOS (разработка)

## Установка

```bash
git clone https://github.com/igordolgov/journal-kpp.git
cd journal-kpp
pnpm install
```

Если pnpm блокирует postinstall-скрипты (обычно на Windows) — в проекте
уже прописан блок `allowScripts` (esbuild, @parcel/watcher, electron-winstaller).
Если pnpm всё же спрашивает разрешение:

```bash
pnpm approve-builds
```

Выбрать все пакеты (a + Enter), затем:

```bash
pnpm rebuild
```

## Разработка

```bash
pnpm dev
```

Открыть: http://localhost:3001/ (порт задан в `nuxt.config.ts`).

    ⚠️ В dev-режиме приложение живёт в браузере: данные пишутся в IndexedDB
    этого браузера (F12 → Application → IndexedDB). У portable exe — своё
    хранилище (userData Electron). Данные dev и exe не смешиваются и
    автоматически не переносятся: то, что наработал симулятор в браузере,
    exe не увидит, и наоборот.

### Запуск на телефоне [№39]

Телефон в той же Wi-Fi-сети, что и ПК:

```bash
pnpm dev:lan          # = nuxt dev --host 0.0.0.0
```

На телефоне открыть `http://<IP-компьютера>:3001/` (IP узнать: `ipconfig`
на Windows). Порт 3001 задан в `nuxt.config.ts`; при первом запуске Windows
может попросить разрешить Node.js доступ к частной сети — разрешить.

Мобильный интерфейс [№39]: меню-«бургер», вкладки «Оформление / Журнал»
на главной, кнопка «во весь экран» в хедере симулятора, крупные тап-таргеты.

Готовую сборку (`pnpm generate`) можно отдать любым статик-сервером,
например: `npx serve .output/public --listen 3001`.

## Тесты

```bash
pnpm test               # разовый прогон (vitest, ожидается 36 passed)
pnpm test:watch         # режим слежения
npx vue-tsc --noEmit    # проверка типов (отдельного скрипта нет)
```

Физика симулятора тестируется чистой функцией `updateAiMovement(dt, cfg)`
без DOM и без Vue: в тестах собирается харнесс со сценой-заглушкой
(калитка, агенты) и прогоняются кадры с фиксированным `dt = 0.1`.

## Сборка Electron (portable exe)

```bash
pnpm generate                          # статическая сборка в .output/public
node scripts/fix-electron-paths.mjs    # абсолютные пути → относительные
pnpm electron:build                    # electron-builder --win portable
```

Результат: `dist-electron/JournalKPP.exe` — портативный, без установки.

⚠️ Почему три команды, а не одна: exe грузит `index.html` через `file://`,
где абсолютный путь `/_nuxt/...` указывает в корень диска и даёт белый
экран. Страховка тройная: `ssr: false` + `router.options.hashMode` +
`app.baseURL: './'` в конфиге, плюс скрипт `fix-electron-paths.mjs`
переписывает пути в готовом HTML (идемпотентен — можно запускать
многократно; если пути уже относительные, файлы не перезаписываются).

⚠️ Правило сборки (проверено болезненно)

1. Ctrl+S всем изменённым файлам; контроль ключевой строки: `rg "маркер" файл`
2. Порядок строгий: `pnpm generate` → `fix-electron-paths` → `pnpm electron:build`.
   Пропущенный `generate` = exe со старым интерфейсом (собирается из
   `.output/public`, а не из исходников).
3. Дочитывать вывод каждой команды до конца (`electron:build` — до
   `building target=portable`).
4. После сборки запустить exe и проверить: принятие смены, проход людей
   и машин, записи журнала.

## Подсистемы

### Симулятор КПП

Ядро — конечный автомат агента в `useSimulatorPhysics.ts`:
`to_gate → waiting_before → crossing → moving_away → waiting_after → done`.
Пешеходы и машины ходят раздельно (калитка / шлагбаум), группы (семьи,
компаньоны) проходят по очереди за лидером, встречные потоки не смешиваются
(очередь направлений, FCFS). Спавн — 4 потока (пешие вход/выход, авто
вход/выход), интервалы по умолчанию в `app/utils/simTuning.ts`
(пешие 60–120 с, машины 90–180 с; пользовательские значения из настроек
имеют приоритет, но не ниже пола).

Анти-застойные предохранители (все пишут в консоль с префиксами
`[watchdog]`, `[crossing-cap]`, `[post-gate-cap]`, `[gate-missing]`,
`[direction-queue]`):

| Предохранитель  | Лимит                 | Действие при срабатывании    |
|-----------------|-----------------------|------------------------------|
| stall-watchdog  | 10 с без сдвига       | телепорт на текущую цель     |
| crossing-cap    | 15 с пеш. / 25 с авт. | перенос в конец прохода      |
| post-gate-cap   | 90 с                  | принудительное завершение (деспавн) |
| direction-queue | 25 с                  | проход вопреки встречному потоку |
| force-cross     | 5 с / 12 с (группа)   | принудительное начало прохода |

Телепорт stall-watchdog срабатывает только на СВОБОДНУЮ цель (нет чужого
корпуса в радиусе 26px от точки) и не трогает машину, которая в этот момент
уступает проезд, — иначе сторож сам создавал «скачок» (машина прыгала на
место ожидания, занятое встречной).

Уступание машин ([БАГ-РЕПОРТ-6]): встречная машина, проезжающая или
уезжающая через мой коридор, заставляет меня либо замереть на подходе
(level 1), либо отъехать задним ходом по своей оси от остановки (level 2:
въезжающая — назад по дороге, выезжающая — вглубь базы, темп 55 px/с,
предел 175 px — [№8] кап выносит отъехавшую за границу зоны прохода,
иначе уезжающая вниз машина вежливо замирает перед отъехавшей навсегда).
Когда коридор свободен (`carCorridorFree`), машина
возвращается на остановку штатным подходом. Пока машина отъезжает, она не
считается «активно ждущей» при закрытии ворот и не участвует в FCFS
(вернётся в конец очереди). Стоп-линия выезжающей машины ([№8]) —
ЗЕРКАЛЬНО въезжающей: передний край спрайта на нижней линии ворот
(раньше бампер недоезжал 18px — «далеко останавливается», фидбек №8).
[№10, правка заказчика] стоящие агенты НЕ прижаты к линии забора:
бампер/подошва въезда — на 6px ВЫШЕ линии дороги (`STOP_STANDOFF_ENTER = 6`),
бампер выезда — на 10px ниже линии (`STOP_STANDOFF_EXIT = 10`).
Точка ожидания закрытия ворот (после прохода) — `CAR_EXIT_PULL_PAST = 46`
выше линии дороги (было 40: поднято вслед за подъёмом остановки въезда,
чтобы сохранить «касание без пересечения» корпусов); выше — «слишком
высоко» (фидбек №6, 60px забракован).

Анимация ходьбы ставится на паузу флагом `el.isPaused`, который считает
физика с гистерезисом (пауза < 0.1, пуск > 1.5 px/s) — без гистерезиса
класс мигал бы в очереди у прохода и «дёргал» руки/ноги спрайта.

Плавность хода ([БАГ-РЕПОРТ-8/9]): в проходе (crossing) пешеход идёт ПО
ПРЯМОЙ — боковое расхождение/дрейф «держись правее» действуют только ДО
прохода (зона ворот) и ПОСЛЕ (moving_away); в дверном проёме зигзаг
выглядел как дёргание. Разгон людей вдвое мягче машинного (естественный
набор шага ~0.8с вместо рывка после медленного подхода); финальное
торможение к точке: человек 11 px/с, машина 24 px/с (экспоненты 0.6/0.7).
Дотягивание ([№9-РЫВОК]): перед ТОЧКОЙ ОСТАНОВА (to_gate у линии, машина
в crossing перед waiting_after) скорость плавно спадает 24 -> 8 px/с у
машины и 11 -> 4 px/с у человека на последних 12/8 px — посадка без
«клевка». Транзитные фазы (человек проходит калитку не останавливаясь)
дотягиванию не подлежат. Поперечник корпуса в проверках препятствий —
ПЕРПЕНДИКУЛЯРНО курсу (машина в профиль: 80 по X, 40 по Y; [№9-КЛИП]).
Регрессионные метрики (реверсы/старт-стоп/синусоичность) —
tests/jitter-diagnostic.test.ts; дотягивание и развязка пары у ворот —
tests/gate-priority.test.ts.

Приоритет выезда ([№9]): если у автомобильных ворот встречаются
въезжающая и выезжающая, ПЕРВОЙ проходит ВЫЕЗЖАЮЩАЯ. Въезжающая не
начинает проход, пока выезжающая занимает свой створ с базовой стороны
(to_gate/waiting_before в зоне 80px ОТ ЛИНИИ ДОРОГИ — [№10] зона 80 по
правке заказчика; меряется от нижней линии ворот, а не от центра
прямоугольника, чтобы высокая геометрия ворот не исключала стоящую на
своей остановке выезжающую), и заранее отъезжает по дороге
(у остановки — назад, на подходе — плавно тормозит к границе створа,
100px до своей остановки; при встречном crossing расчистка на 40%
быстрее). Выезжающая не ждёт FCFS у въезжающей на дороге. Задний ход
уступающей не бьёт корпус сзади (страж оси отъезда 85px). Раньше FCFS
пускал въезжающую первой — она заезжала в корпус выезжающей, и пара
расходилась только по предохранителям (25/90с).

Гудок машин ([БАГ-РЕПОРТ-8/9/10]): сигнал подаётся ТОЛЬКО машиной, долго
ждущей у ЗАКРЫТЫХ ворот (waiting_before, ворота закрыты и не анимируются
дольше 15с ([№10] правка заказчика, было 12/8) + персональная фаза 0..3с),
повтор не чаще 15с. Случайные гудки у едущих машин убраны. Слой z ([№8]):
входящие люди рисуются НИЖЕ выходящих (130-idx против 150/400+idx).

Плавность рендера ([№10-РЫВОК-ДОТЯГИВАНИЯ]): агенты позиционируются
`translate3d` (композитный слой, субпиксельное смещение), а НЕ left/top:
left/top вызывали пересчёт layout каждый кадр, а SVG-растр внутри
масштабированной сцены привязывался к целым физическим пикселям — на
медленном дотягивании (8-24 px/с) это выглядело как прыжки по 1px.
Физический профиль торможения монотонен без скачков — регрессия S8/S9 в
tests/jitter-diagnostic.test.ts (макс. Δv/кадр = пределу торможения,
шаг не длиннее velocity*dt).

Улучшения «как в жизни» (№11 — решения по П1..П8 спецификации):

- П1: темп шага анимации пропорционален скорости — на дотягивании ноги
  семенят реже (фаза цикла `settings._walkHold` растёт пропорционально
  пути, CSS — через `var(--walk-hold)`); тесты `walk-pace`. В №12
  переписано: ноги никогда не быстрее естественного темпа (см. ниже).
- П2: потолок разгона машин 60 px/с² при любом ACCEL (люди — ACCEL/2);
  тесты `car-accel-cap`.
- П4: гудок «би-би» — бип 0.3 с + пауза 0.15 с + бип 0.3 с (`useAudioEngine`).
- П6: шлагбаум закрывается ПОСЛЕ расчистки створа (80 px от линии дороги),
  а не от момента посадки; машина уезжает с посадки через 0.8 с, не дожидаясь
  закрытия; вошедший в створ корпус снимает отсчёт; очередь держит ворота;
  тесты `gate-close-sweep`.
- П7: индивидуальный темп людей 0.85–1.15 на спавне, у группы общий;
  тесты `pace-variance`.
- Отклонены заказчиком: П3 (MIN_BUFFER 30), П5 (крейсерская 70), П8 (дуга).
- Заодно устранён дефект взаимной вежливости: отъезжающая уступающая
  (отъезд активен) больше не «стена» для пересекающей — пара не мёрзнет
  (`turn-alternation`, `gate-priority` переписаны под новую семантику).

Фикс №12 (баг-репорт: ноги при торможении, разъезд машин во дворе):

- Ноги без «ускорения при торможении»: раньше накопленная пауза сдвигала
  фазу CSS-анимации вперёд — при замедлении ноги перебирали ЧАЩЕ (до 2x
  на месте). Теперь фаза шага растёт пропорционально пройденному пути
  (`walkHoldStep = dt * v / cruise`): торможение — шаг реже, остановка —
  ноги замерли (класс `is-paused`); быстрее естественного темпа — никогда.
  Тесты `walk-pace` (монотонность, потолок dt за кадр).
- Разъезд машин внутри территории: въехавшая после прохода стоит на оси
  ворот, выезжающая поднимается по ТОЙ ЖЕ оси — «лоб в лоб», коридор уезда
  вниз занят. Новое правило [M16]: въехавшая уезжает НАЛЕВО по своей
  полосе за левый край (afterTarget переписывается — сторож не вернёт её
  вниз), освобождая путь выезжающей; работает и при старте уезда, и в
  движении. Коридор свободен — канонический уезд вниз без изменений.
  Тесты `car-left-departure` (4 сценария), `car-corridor-yield` обновлён.
Фикс №13 (основное правило безопасности КПП + поведение людей):

- Ворота никогда не остаются открытыми (частично или полностью) без машин
  рядом. Машина на посадке (`waiting_after`) после вежливой паузы 0.8 с
  ждёт ПОЛНОГО закрытия своего шлагбаума и уезжает за опущенной стрелой;
  «частично открытые» ворота (анимация опускания) закрытием не считаются.
  Отсчёт закрытия стартует, когда ни один корпус не ПЕРЕКРЫВАЕТ линию
  дороги F (точный тест пересечения линии корпусом): шлагбаум опускается
  за спиной машины на посадке и ПЕРЕД очередью. Легальная очередь
  (`waiting_before` у своих ворот, включая уступающих) держит ворота
  открытыми — конвой проходит через одно открытие, последняя машина
  закрывает за собой стрелу. Предохранитель `gateCloseWaitMax` = 45 с —
  на случай «ворота не закроются никогда». Калитка включена в свип
  закрытия (пустая открытая калитка закрывается через 2 с). Тесты
  `gate-close-sweep` (переписан), `traffic-scheme`, `antiteleport`,
  `gate-priority`, `turn-alternation`, `stuck-targets`.
- Люди не проходят друг сквозь друга: торможение перед пешеходом и мягкое
  расхождение (шаг вбок) действуют по ВСЕЙ сцене, а не только в зоне
  прохода. Встречные расходятся дрейфом «держись правее» (только на
  встречного или стоящего впереди — от попутчика догоняющий просто
  тормозит и идёт следом, без зигзага); в дверном проёме и в тихой зоне
  прибытия расхождений по-прежнему нет. Тесты `pedestrian-flow`
  (встречные на дороге и в базе).
- Люди вообще не ускоряются: рампа разгона убрана (была ACCEL/2), скорость
  сразу равна целевой — фаза ног (∝ пути с №12) не набирает темп, шаг с
  места идёт в естественном ритме CSS-анимации. Плавный разгон остался
  только у машин (60 px/с²). Тесты `car-accel-cap`, `pause-hysteresis`.
- Производные исправления: метрика leader-follow машин заменена на точный
  осесимметричный тест прямоугольников (касание полос въезда/выезда
  больше не «помеха» — иначе въезжающая замирала «стой-иди» за ожидающей
  закрытия выезжающей); уступающая машина учитывается в очереди закрытия.
Фикс №14 (плавность в разработке — рендер выведен из реактивности Vue):

- Диагноз: «дёргания» в браузере при dev-запуске — НЕ квантование пикселей
  (эксперимент в headless Chromium при DPR 1 / 1.25 / 1.5 показал
  субпиксельно плавное движение и в старой, и в новой схеме раскладки), а
  ВРЕМЯ КАДРА: физика мутирует x/y реактивных агентов, шаблон виджета читал
  их через :style/:class — рендер был подписан на позиции ВСЕХ агентов, и
  Vue пересобирал весь виджет каждый кадр. Production (exe) успевал в
  бюджет кадра 16.6 мс, dev-режим (Vite/HMR, дев-рантайм Vue) — нет: кадры
  срывались, а на дотягивании (8-24 px/с) каждый пропущенный кадр удваивает
  шаг движения.
- Решение (классический game-loop): Vue отвечает только за структуру
  (спавн/деспавн, клики, настройки), покадровые стили пишет paintScene()
  из gameLoop напрямую в DOM: transform/zIndex агентов, пауза конечностей и
  фаза шага (--walk-hold), лейблы (заодно переведены на translate3d —

### Повседневный workflow

1. Перед началом работы — подтянуть свежие изменения:

```bash
git pull
```

2. Поработать, внести изменения.

3. Посмотреть, что изменилось:

```bash
git status
git diff
```

4. Добавить изменения в индекс:

```bash
git add .                                # все файлы
# или выборочно:
git add app/components/SimulatorWidget.vue
```

5. Сделать коммит:

```bash
git commit -m "fix: убрать дёргание спрайтов у калитки"
```

Формат сообщений:

- `feat:` — новая функциональность
- `fix:` — исправление бага
- `docs:` — документация
- `chore:` — рутина (обновление зависимостей, чистка)
- `refactor:` — рефакторинг без изменения поведения
- `style:` — форматирование

6. Запушить на GitHub:

```bash
git push
```

Если забыли `git pull` и получили `! [rejected]`:

```bash
git pull --rebase origin main
git push
```

`--rebase` аккуратно «переложит» ваши локальные коммиты поверх удалённых.

### Передача коммитов без пуша (git bundle)

Если на машине нет учётных данных GitHub (push невозможен, например
нет токена), коммиты переносят посылкой-бандлом:

```bash
# на машине с коммитами — собрать посылку
git bundle create journal-kpp-unpushed-commits.bundle origin/main..main
```

На машине-получателе (файл положить, например, в корень диска D:\):

```bash
git pull origin main                                   # 1. синхронизироваться с GitHub
git pull "D:\journal-kpp-unpushed-commits.bundle" main # 2. применить посылку
git push                                               # 3. отправить всё на GitHub
```

⚠️ Бандл требует базовый коммит — тот `origin/main`, на котором он
собирался. Без шага 1 будет ошибка
`error: Repository lacks these prerequisite commits`. Порядок строгий:
сначала `git pull origin main`, потом бандл, потом push.

### Если что-то сломалось

Проверить, к какому репозиторию привязан проект:

```bash
git remote -v
```

Должно быть:

```
origin  https://github.com/igordolgov/journal-kpp.git
```

Если URL другой:

```bash
git remote set-url origin https://github.com/igordolgov/journal-kpp.git
```

Проверить, что ветка связана с удалённой:

```bash
git status
# должно быть: "Your branch is up to date with 'origin/main'"
```

Если push говорит `no upstream branch`:

```bash
git push -u origin main
```

Флаг `-u` нужен только один раз — потом `git push` работает без аргументов.

## Известные проблемы и уроки

### Белый экран в exe

Симптом: exe запускается, окно пустое. Причина: абсолютные пути `/_nuxt/...`
в HTML при загрузке через `file://`. Решение — раздел «Сборка Electron»:
`pnpm generate` → `node scripts/fix-electron-paths.mjs` → `pnpm electron:build`.

### Windows + обновления Nuxt

Раньше Nuxt 4.6.0 на Windows падал с ошибкой
`Either manifest or precomputed data must be provided` в
`vue-bundle-renderer` (на Linux та же версия работала). Перед обновлением
Nuxt проверяйте сборку на Windows; при воспроизведении закрепите
последнюю рабочую версию в `package.json` без `^`.

### pnpm блокирует postinstall

Симптом: `ERR_PNPM_IGNORED_BUILDS`, отсутствие нативных бинарников
(esbuild, @parcel/watcher, electron). Решение: блок `allowScripts` в
`package.json` уже прописан; если pnpm всё равно спрашивает —
`pnpm approve-builds` → выбрать все → `pnpm rebuild`.

### Перенос с Linux на Windows

Удалить `node_modules/`, `.nuxt/`, `.output/`, `pnpm-lock.yaml`, затем
`pnpm install` — пересобрать нативные бинарники.

### Зависания агентов в симуляторе

Симптом: агент стоит на месте («вошёл и замер»). Диагностика: открыть
консоль (F12 в dev / devtools Electron) и искать префиксы
`[watchdog]`, `[crossing-cap]`, `[post-gate-cap]`, `[direction-queue]` —
каждое срабатывание логируется с типом и id агента. Правильный фикс —
устранить причину (цель, геометрия сцены), а не отключать предохранители:
они страховочные, штатно не срабатывают.

### Локальная копия отстала от GitHub

Симптомы: `git push` отклонён — `! [rejected] main -> main (fetch first)`,
«remote contains work that you do not have locally»; бандл не применяется —
`error: Repository lacks these prerequisite commits`. Причина: коммиты
попадали на GitHub в обход этой машины (веб-редактор GitHub, вторая
машина). Решение: сначала `git pull origin main`, и только потом бандл
и push. Проверка: `git log --oneline -5` — верхний коммит локальной
ветки должен совпадать с `origin/main`.

### IndexedDB и миграции

Миграция выполняется в `onupgradeneeded`: создаются только недостающие
сторы, данные не трогаются (v11 добавил store `payroll`). При отладке
очищать БД через страницу `/database`, а не удалением файлов.

## Соглашения по коду

- Компоненты: PascalCase (`SimulatorWidget.vue`)
- Composables: camelCase с префиксом `use` (`usePayroll.ts`)
- Типы: в `app/types/` или локально в `<script setup>`
- Стили: TailwindCSS utility-классы, кастомные — в `app/assets/css/`
- В pug-шаблонах классы со спецсимволами (`hover:bg-*`, `py-2.5`, `lg:block`)
  — только внутри `class="..."`; точечный синтаксис — только классы из
  букв/цифр/дефисов
- Комментарии: на русском, для сложной логики — «почему», а не «что»
- Физика симулятора — единственный источник правды о состояниях агентов;
  UI не дублирует вычисления
- Начисления (payroll): суммы, капы и дедупликацию считает только движок
  `usePayroll`, компоненты только показывают
- Идемпотентность: повторные операции не дублируют эффекты
  (`dedupe_key` в payroll, `fix-electron-paths.mjs` перезаписывает файлы
  только при реальных заменах)
- Коммиты — conventional commits

## Лицензия

Учебный проект. Свободное использование в образовательных целях.

Фикс №32 (звук мотора на закрытых воротах, замирание-скольжение перед
точками ожидания):

- «ЗАКРЫТЬ» на уже закрытых воротах больше НЕ включает холостой запуск
  мотора: раньше кнопка запускала твин 0 -> 0 на весь closeDuration с
  зацикленным звуком — створ неподвижен, мотор гудел до «СТОП». Створ в
  целевом положении финализируется сразу, без твина и звука (то же для
  «ОТКРЫТЬ» на открытых). Перехват идущей анимации кнопками работает как
  раньше. Бонус: машины после проезда не ждут лишние секунды холостого
  «закрытия».
- Люди у точек ожидания больше не «замирают как бы скользя» и не
  перескакивают на миллиметры: старый ползучий профиль (11 -> 4 px/с на
  последних 8px + снап до 1px) заменён равнозамедленным подходом
  v = √(2·a·d) — человек идёт своим темпом и плавно останавливается ровно
  в точке; посадка — штатным шагом кадра, последний шаг — доли пикселя.
  Новый ползунок в панели «Движение и логика людей» (окно симулятора и
  Настройки): «Торможение у точки останова» (pArriveDecel, 30..300 px/с²,
  дефолт 110), применяется на ходу. Машины не тронуты («идеальны» с №27).

Фикс №33 (уверенный подход заезжающей, ранний уезд заехавшей, трескучий
звук привода, запрет выделения UI, дети среди агентов):

- «Заезжающая машина, которой уступили, не притормаживает»: триггер
  уступания «встречная в crossing» стал геометрическим — пока корпус
  выезжающей на полосе, заезжающая уступает; выехавшая со створа больше
  не тормозит её. Отъезжающая задним ходом выезжающая не считается
  помехой (она уже уступает), а следование за отъезжающим вдоль курса
  лидером не даёт жёсткого стопа — только мягкий кап, без «тормоз в
  ноль -> стояние -> рывок». Безопасность сохранена: стоящая на полосе
  машина по-прежнему останавливает заезжающую.
- «Заехавшая машина не ждёт закрытия ворот, если другая выезжает»:
  ранний уезд налево срабатывает сразу после вежливой паузы при любом
  состоянии шлагбаума, если выезжающая подъезжает/проходит/стоит в
  очереди — ось ворот освобождается без цикла закрытия-открытия
  (раньше — до 10с свипа или до 45с предохранителя).
- Звук привода ворот — «как в жизни»: гул мотора с механическим треском
  зубьев шестерни (щелчки 4-10мс с рандомным интервалом/амплитудой) и
  редким скрипом (2 вставки на 6-секундный цикл, вибрато + глиссандо).
- Кнопки и подписи к ним невозможно выделить двойным кликом/драгом:
  user-select: none для всех кнопок/label и всего окна симулятора.
- Дети теперь видны: спрайт ребёнка 72% взрослого роста; ребёнок не
  ходит один — всегда в группе со взрослым опекуном из семьи (раньше
  ageGroup не влиял на размер спрайта, и дети выглядели как взрослые,
  а выпадая лидером, шли поодиночке).

Фикс №34 (выхавшая уезжает сразу, заезжающая заезжает в открытые ворота):

- Репорт: «выхавшая машина (грузовик) уступила подъезжающей легковой
  (поднялась выше на посадку), но не уехала сразу — ждала закрытия
  ворот; и легковая тоже не заезжала в открытые ворота, а ждала
  закрытия». Причина: ранний уезд выезжающей требовал полного закрытия
  ворот ([№27]), а подъезжающая (ещё не вставшая в очередь у линии)
  этого уезда не разрешала — и сама не могла встать в очередь, пока
  выезжающая занимала створ. Взаимное ожидание длилось до срабатывания
  свипа закрытия (gateCloseDelay, по умолчанию 10с).
- Теперь выезжающая уезжает СРАЗУ после вежливой паузы 0.8с, если
  въезжающая претендует на ось ворот (стоит или подъезжает: корпус или
  цель в коридоре оси), при любом состоянии шлагбаума — створ уже
  пройден, посадка линию шлагбаума не перекрывает. Безопасность
  сохранена: уезд выполняется только корпусом выше полосы въезда
  (машина, ещё стоящая на линии ожидания, сначала поднимается
  корректором на посадку и уезжает следующим кадром); при занятых обеих
  сторонах дороги уезда по-прежнему нет (репорт №27); у пустых ворот
  машина ждёт полного закрытия (репорт №23).
- Легковая после уезда грузовика свободно доезжает до линии и заезжает
  в открытые ворота — без цикла закрытия-открытия.
