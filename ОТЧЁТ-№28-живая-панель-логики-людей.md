## 1. Запрос

> «добавь все эти настройки движения и логики людей в окно симулятора (только компактно), чтобы я мог изучать их действия во время работы симулятора.»

Ключевые требования:
- **в окно симулятора** — панель поверх сцены, не на отдельной странице;
- **только компактно** — узкая, не перекрывает обзор, прокрутка;
- **изучать во время работы** — изменения должны действовать сразу, на бегущей симуляции.

## 2. Что было до №28 (и почему «на ходу» не работало)

Карточка «Движение и логика людей» существовала в «Настройки -> Симулятор» (№27), но:
1. Она на отдельной странице — во время симуляции недоступна.
2. Заявленное «применяется на ходу» фактически не работало: `useSimulatorPhysics`
   считывал все 23 параметра из `simOpts.personTuning` **один раз при создании**
   (`const PERSON_TURN_TAU = tuneNumber(...)`, …) и хранил их в константах замыкания.
   Живой оставалась только ссылка на объект — но не производные константы. Правка
   ползунка при работающей симуляции ничего не меняла до перезапуска виджета.

## 3. Реализация

### 3.1. Физика: живое чтение настроек (useSimulatorPhysics.ts)

- Все 23 параметра логики людей переведены из `const` в `let`:
  `PERSON_TURN_TAU`, `COLLAPSE_STUCK_S`, `COLLAPSE_BREAK_S`, `personCollapseOn`,
  `personAccelOn`, `PERSON_ACCEL`, `personYieldOn`, `PERSON_WAIT_YIELD_RADIUS`,
  `PERSON_SEP_SPEED`, `PERSON_YIELD_AVOID`, `personNearCapOn`, `PERSON_SEP_RADIUS`,
  `personStandStopOn`, `PERSON_STAND_STOP_DIST`, `personBypassOn`,
  `PERSON_BYPASS_RADIUS`, `PERSON_BYPASS_SPEED`, `personHardSepOn`, `PERSON_HARD_SEP`,
  `PERSON_HARD_SPEED`, `ARRIVE_QUIET_ZONE`, `FORCE_CROSS_AFTER`, `FORCE_CROSS_GROUP_AFTER`.
- Добавлена единая функция `refreshPersonTuning()`: перечитывает **свежую ссылку**
  `simOpts.personTuning` и все значения (с клампом по реестру). Вызывается при
  создании физики и **в начале каждого тика** `updateAiMovement`.
  - Значения применяются мгновенно, посреди движения агентов — без пересоздания физики.
  - Подхватывается даже полная замена объекта (мерж конфига при загрузке сейва).
  - Стоимость: ~23 поиска по реестру из 17 полей на тик — пренебрежимо.
- Аварийный клапан `arriveFadeOf` продолжает корректно работать при изменении
  `pQuietZone` на ходу (читает `let`-переменную, включая 0 = «без тихой зоны»).

### 3.2. Компактная панель в окне симулятора (SimulatorWidget.vue)

- **Кнопка** в шапке симулятора (иконка человека, `PersonStanding` из Lucide) рядом
  с кнопкой «Настройки». Активное состояние — зелёная подсветка. Открытие одной
  панели закрывает соседний поповер «НАСТРОЙКИ» (не наслаиваются).
- **Панель**: `.absolute.top-11.right-2.z-50.w-72` (288 px), тёмная карточка в стиле
  существующего поповера, `max-h-[calc(100%-3.5rem)]`, внутренний список
  `overflow-y-auto` — прокручивается внутри любого размера окна симулятора.
- **Содержимое**: все 17 ползунков + 10 тумблеров реестра `PERSON_TUNING_FIELDS`,
  сгруппированные в 4 секции заголовками: «Обход и уступание», «Дистанции и стопы»,
  «Плавность хода», «Предохранители».
- **Строка параметра**: тумблер механизма (если отключаем) + название (подсказка —
  в `title`) + текущее значение с единицами моноширинным шрифтом + ползунок
  `range-xs` (шаг и диапазон — из реестра). Выключенный механизм приглушён
  (`opacity-40`), но значение регулируется заранее.
- **Кнопки панели**: «сохранить» — `saveConfig()` (значения переживают перезапуск
  приложения и видны в «Настройках»), «сброс» — возврат всех значений к дефолтам.
- **Модель данных**: `ptModel` — computed, возвращающий `props.simSettings.personTuning`
  (общий объект с `config.simulator`: правки синхронны с карточкой настроек) либо
  локальный `reactive`-фолбэк из дефолтов. В `physicsSimOpts` добавлено own-свойство
  `personTuning` с геттером — панель работает во всех трёх точках запуска симулятора,
  включая `scenario-editor.vue`, где `sim-settings` не передаётся.

### 3.3. Реестр (personTuning.ts)

- В `PersonTuningField` добавлено обязательное поле `group: string`; все 17 полей
  распределены по 4 секциям. Карточка «Настройки -> Симулятор» осталась без изменений
  (поле просто не используется там) — обратная совместимость полная.
