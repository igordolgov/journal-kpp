# Отчёт №35 — обновление @types/node до 26.6.5, TypeScript 7.0.2 — пока нельзя

## Вопрос

> можно ли теперь обновить модули в этом проекте @types/node до 26.6.5 и
> typescript до 7.0.2? раньше были проблемы

## Ответ (коротко)

- **@types/node 26.6.5 — ДА, можно и готово** (поставка №35). Все ворота
  качества зелёные: vue-tsc 0 ошибок, тесты 320 passed | 1 skipped,
  nuxt generate ОК — проверено на чистом стенде.
- **typescript 7.0.2 — НЕТ, пока нельзя.** Это нативный (Go) компилятор,
  из которого удалён JS-API, а vue-tsc (последняя версия 3.3.13) работает
  именно через JS-API и падает сразу при запуске. Проверено на стенде.

## TypeScript 7.0.2: почему нельзя (доказательства)

1. **Устройство пакета.** `typescript@7.0.2` — нативный порт: зависимости
   пакета — платформенные бинарники `@typescript/typescript-{linux-x64,
   win32-x64,...}`; в `lib/` лежит только загрузчик (`getExePath.js`,
   `tsc.js`, `version.cjs`); поле `exports` отображает корень пакета на
   `./lib/version.cjs`. JS-API компилятора (`ts.createProgram`, `lib/tsc`,
   файлы `lib/lib.*.d.ts` на диске) из пакета удалён. Сам CLI `tsc`
   работает: `pnpm exec tsc --version` → `Version 7.0.2`.

2. **vue-tsc падает мгновенно.** На стенде (проект + typescript 7.0.2):
   ```
   Error [ERR_PACKAGE_PATH_NOT_EXPORTED]: Package subpath './lib/tsc' is
   not defined by "exports" in .../node_modules/typescript/package.json
   ```
   `vue-tsc 3.3.13` — последняя существующая версия (dist-tags: latest =
   3.3.13, v3.0 = 3.0.11); версии с поддержкой нативного TS нет.
   Формальный peer-range `typescript: '>=5.0.0'` upper bound не имеет,
   но фактическая совместимость отсутствует.

3. **Моста нет.** Стабильная линия TypeScript: 5.9.x → 7.0.x; ветки 6.x
   с JS-API в registry нет (есть только 7.1.0-dev...). Пакет
   `@typescript/api` не существует; `@typescript/native-preview` — dev-
   сборки. То есть «промежуточного» обновления типа «TS 6 с сохранением
   JS-API» не существует.

4. **Что при этом живёт на TS 7** (проверено на стенде, для полноты):
   vitest — 320 passed | 1 skipped (vitest typescript как библиотеку не
   импортирует), `nuxt generate` — ОК (транспиляция через oxc/esbuild).
   Ломается именно контроль типов через vue-tsc — главный инструмент
   качества проекта. knip в этой Linux-среде падает и БЕЗ TS 7
   (oxc-биндинг контейнера) — к обновлению отношения не имеет, на
   Windows ведёт себя как прежде.

   Вывод: обновить typescript до 7.0.2 можно будет, когда выйдет
   vue-tsc/Volar с поддержкой нативного TypeScript (либо когда проект
   откажется от vue-tsc). Остальной конвейер к этому уже готов — на
   стенде TS 7 ничего, кроме vue-tsc, не сломал.

## @types/node 26.6.5: почему можно (доказательства)

1. **Пиры удовлетворены:** nuxt 4.6.2 требует `@types/node >=18.12.0`;
   vitest 5.0.5 — `^22.0.0 || >=24.0.0`. vue-tsc/knit ограничений на
   @types/node не имеют.

2. **Найден след «прошлых проблем»:** в `pnpm-workspace.yaml` было
   жёсткое перекрытие `overrides: '@types/node': '24.1.0'` — кто-то уже
   прибивал версию типов. Обновление выполнено в ОБЕИХ точках
   (package.json + overrides), иначе pnpm молча оставил бы 24.1.0.

3. **Чистый прогон на стенде** (копия проекта, pnpm 10.34.9,
   ELECTRON_SKIP_BINARY_DOWNLOAD, lockfile от базы №34):
   - `pnpm list @types/node` → 26.6.5 (override подтверждён);
   - `pnpm exec vue-tsc --noEmit` → 0 ошибок;
   - `pnpm test` → 320 passed | 1 skipped | 0 failed (43 файла);
   - `pnpm generate` → ОК.

4. **Lockfile.** Перегенерирован pnpm 10.34.9; дифф 1640 строки, из них
   функциональное изменение одно — @types/node 24.1.0 → 26.6.5. Остальное
   — безобидное приведение формата вашей версией pnpm: удаление
   peer-суффиксов `supports-color@10.2.2` у записей, выравнивание
   ссылок импортёра на уже присутствовавшие в lock-файле дубли
   `@vue/compiler-sfc@3.5.44` (совпадает с прибитым vue 3.5.44) и
   `@oxc-project/types@0.154.0`. electron-builder остаётся 26.17.0,
   electron 45.0.0 — без изменений.

5. **Замечание о рантайме.** @types/node описывает API Node.js для
   проверки типов при разработке; рантайм приложения — Electron со
   своим встроенным Node, на сборку и работу exe обновление типов не
   влияет. Косвенная польза: свежие типы точнее документируют Node-API,
   доступные в dev-скриптах (pnpm/node на машине разработчика).
